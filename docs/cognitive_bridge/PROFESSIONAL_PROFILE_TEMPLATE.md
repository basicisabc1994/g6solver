# Template — professional evidence and acceptance standard

**Template only. Not an authoritative or independently accredited professional standard.** A qualified expert must adopt and cite the actual governing authority, jurisdiction, edition and original source bytes before any professional use.

## Task contract (complete before agent work)

| Field | Required content |
|---|---|
| Intended task and economic value | User's actual requested result and why it matters |
| Permitted scope | Deliverables, exclusions, data/implementation limits |
| Risk tier R0–R3 | Severity of a false acceptance and downstream consequences |
| Governing standard | Issuer, title, edition, jurisdiction, publication/retrieval dates and canonical source digest |
| Claim decomposition | Each material subclaim; expected evidence type, confidence limitations |
| Formalisation ownership | Named reviewer who checks that natural language was faithfully translated |
| Evidence provenance | Original source artifacts, versions, dates, ownership and licensing |
| Independent acceptance test | Verifier ID, rationale, executable method, independent test custody, positive and planted-negative cases |
| Uncertainty disposition | Unknowns, conflicting evidence, untested boundary cases, explicit escalation threshold |
| Professional review | Competence, authenticated identity, separate scope-bound signature, when risk requires it |
| Reproduction | Environment/inputs/code versions/artifact checksums and commands to rerun |
| Release authority | Who can accept, release, publish or act on result (never the generator alone) |

## Suggested domain-specific considerations

**Software engineering** — requirement-to-test coverage, static and dynamic safety properties, tenant isolation, regression prevention, build/test execution in a real OS boundary, dependency provenance, failure injection and mutation sensitivity, CI reproducibility, observability and documented excluded platforms. A passing unit test does not certify whole-system correctness.

**Scientific research** — preregistered hypothesis, competing mechanisms, randomisation/control design, appropriate statistical uncertainty and multiple-testing correction, sensitivity analysis, data/code provenance, causal identification assumptions, scientific novelty review, replication on independent data, and disclosure of null outcomes. A strong model fit alone does not validate a causal discovery.

**Medical, dental, financial or legal work** — jurisdiction-specific law, regulation, current evidence, competence and supervision, informed consent where applicable, client/patient-specific facts, calibrated uncertainties and traceable professional sign-off. The current code is **not** an approved professional decision system and must not replace regulated professional judgment or required review.

## Certificate admission checklist

A candidate dossier can be assembled only when each declared acceptance criterion is linked to a verifiable artifact and an evaluator-owned replay route. An externally certified result additionally requires authentication of the issuer, verification of current source authority, independent replay under the real G6 promotion law, appropriate professional review and operator release authorisation.

`qualified-draft` means the evidence package is useful for review within its scope. It does **not** mean the work is finished to a professional standard unless that professional's independently authenticated acceptance procedure explicitly says so. `blocked-escalated` means one or more required gates could not establish the obligation.
