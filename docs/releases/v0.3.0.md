# v0.3.0 beta preparation — not published

This note goes with the draft pull request that brings the 0.3 line into `main`. The wiring work is integrated on
`claude/wiring-int` and goes into the issuance line `claude/issuance-0.3b`; the distillation work is on
`claude/distill-int`. Nothing here is tagged, released or published, and v0.1.0 stays immutable. Merging, tagging,
publishing to PyPI and deploying the site are the owner's steps.

Status: early alpha. Individual capabilities have been tested; general application-level improvements have not yet
been established.

The beta label waits for the beta gate below. Until every row of it is met, this line stays early alpha.

## How to start

1. Make G6 an environment of its own with `python -m venv --copies`, then `pip install ".[all]"` into it from G6's
   repository. On Linux, G6 cannot yet tell its own Python from a project environment linked to the same one, and
   refuses to review then.
2. Run `g6 setup --client claude` or `g6 setup --client codex`. Setup registers the MCP server with the client and
   installs the `using-g6` skill. For Codex it offers G6's block for `AGENTS.md` and writes it only on the person's
   yes. Patch review runs code, so the person allows it once with
   `g6 setup --client claude --allow patch_review.review`.
3. Start a coding session as usual. The server's instructions tell the agent when to reach for G6: before it says a
   Python task is done, when it is stuck, and after a G6 refusal. In those moments it calls `g6_select` with the task,
   its phase and the refusal's code.

## What 0.3.0 adds

The MCP server has 58 tools on the integration line (counted from `g6.mcp.build_server()` on `claude/wiring-int`).
The distillation line adds 12 more.

### G6 at the moment of need

- **One text, three places.** A short text (at most 150 words, coding first) says when to reach for G6. It is the MCP
  server's `instructions`. With the person's agreement, `g6 setup --client codex` writes it into Codex's
  `AGENTS.md`, as a delimited block that setup replaces and nothing else. Its first sentence also ends the hint a task
  starts with.
- **The hint.** When a task starts, the prompt hook adds at most 60 words that point to `g6_select`. It never repeats
  the prompt. It is off when the person's key file says `G6_HINTS=off`.
- **The plugin** ships the `using-g6` skill, byte for byte the same as the one setup installs.
- **G6's own catalogue is public.** `g6_find`, `g6_describe` and `g6_components` answer for built-in components with
  no sharing grant. An installed extension's text, the person's data, repository source and knowledge sources still
  need the person's grant.

### Choosing the next call: `g6_select`

- `g6_select` takes the task, the phase (`plan`, `implement`, `verify`, `diagnose` or `stuck`), the last outcome or refusal
  code, and the calls the agent is already considering.
- It returns at most 8 candidates from one corpus: MCP tools, skill routes and runnable built-in operations. Each
  candidate has an exact call template, what it establishes, what it needs and its cost.
- Each candidate says in `validated` whether G6 checked its template against the tool's schema or ran it as given,
  and lists in `fill` the values the agent still supplies. Nothing runs. The reply's state is `qualified-draft`.
- It needs no grant and reports no fact about the host, so it answers on a fresh client.

### When a call is refused: the repair block

- Every refused or blocked reply over MCP gains a `repair` field. It says who repairs the refusal (the agent or the
  person), the step in G6's words, and, where the agent can act, a call template G6 checked.
- A refusal is never retried unchanged, and retries are counted per tool and code in each session. Nothing in the
  block grants anything or answers for the person.
- G6 keeps an append-only repair log with codes and ids only (`repairs/repairs.jsonl` in G6's state folder), and
  reads its resolution rate by code from it.

### A model by default (`claude/model-default`)

- With no provider named, each model call uses the calling Claude Code or Codex sign-in if it is installed, then the
  other installed host, then plain code. Steps that need a model say so when none is available.
- A send to the same provider as the calling client needs no dialog for the current request, for repositories inside
  the client's declared workspace roots, and for G6's operational data. Each such send is kept in the disclosure log.
  Other sources, other recipients, unknown clients and Python calls still need the person's grant. A recorded revoke
  or decline still wins.
- `G6_LLM_PROVIDER=none` in the key file opts out, and settings in the environment cannot undo it. `G6_DISABLE_LLM`
  stops model calls.
- The default covers model calls without tools. Scouts, tool sessions and agent runners need their provider named in
  the key file.

### Model proposals that never decide (`claude/wire-semantic-followup`)

- `g6_select` can let the model reorder the offered candidates (`rerank="model"`). The model never adds a candidate or
  changes a call, and every call is checked as before.
- `g6_premortem` takes the agent's own hypotheses (claim, prediction, check), or model proposals with `propose`. A
  hypothesis is kept only when its check is one G6 can run; the rest are listed as untestable, with the reason. Model
  proposals are labelled `model_proposal` and never set a standard.
- With no model, a model error or a withheld consent, the order stays lexical and the reply says why.

### The override kernel v1: `g6_agentic_run`

- When a component fails or reaches a limit it declares, or when the caller asks after a successful answer, a model
  can stand in for a declared part of the computation. The original runs first; the trust doors' refusals never
  trigger an override, and code mode is refused.
- The substitute runs in a confined child process. Each substituted value must pass its return type and the declared
  validator, and the final answer must pass the declared checker in a fresh confined run.
- The reply names the model and keeps the original answer beside it. Its state is `qualified-draft` at best, with a
  warning card. A substitute never passes a requirement and never becomes evidence in another G6 check.
- The ledger records what decided each send: provider consent, a local model, allowed in code, or refused by the
  consent check.
- Only the owned host sign-in, local models and loopback endpoints qualify. Cloud endpoints and the Anthropic SDK are
  refused for overrides in v1.

### Learning from recorded outcomes (`claude/wire-learn`)

- A proposed check that caught a defect is kept and replayed on later tasks, with proposed authority only. Trials
  are admitted only from G6's own receipts.
- `g6_select` ranks with that recorded history. It gives the same reply as before when nothing is recorded.
- `learning_history`, a component reached through `g6_invoke`, lists a repository's history. It forgets that history
  only after the person agrees in the client's dialog.
- Nothing here is measured as a benefit: see "Not yet measured".

### Distillation, self-rectification and the self-model (`claude/distill-int`)

These ship built and wired, with no measured benefit. The study that would measure one has not run (see "Not yet
measured").

- **Failure records.** `g6_failure_record` keeps a reported failure or request on the person's machine. Over MCP the
  record is self-observed field data, never independent evidence.
- **Distillation.** `g6_distill_start` and `g6_distill_job` turn independent training failures into a concept, then
  into proposed executable checks. A separate acceptance gate admits a check into the library only against a frozen
  registration, held-out cases and its statistical bars. Starting distillation runs code, so the person must allow it.
- **The library.** `g6_library` lists the current methods and describes a method or its authority history.
  `g6_library_decide` asks the person, in the client's dialog, to demote or withdraw a method. A decline or a changed
  entry changes nothing, and restoring a method needs a new independent acceptance.
- **Self-rectification.** `g6_extend` records a capability request. A request grants no authority.
- **The self-model.** `g6_self_model` reads G6's state, each value with its source and lifetime: over MCP, the stop
  and the authority level are read, while budget room and isolation read as unknown. A stale value reads as unknown.
  `g6_simulate` predicts an action's outcome; predictions never count as acceptance evidence.
- **The research runner.** `g6_research_start`, `_stop`, `_status` and `_digest` run, stop and report bounded research
  ticks. Research authority is off by default (`self_training/autonomy.json`), and a start needs the person's dialog.
- The `using-g6` skill routes to these tools (`references/learning.md`), and the plugin's hook covers them.

### Carried from the earlier 0.3 work

- **Consent before any cloud model** (`g6_cloud_grant`, `g6_cloud_grants`, `g6_cloud_revoke`, `g6_disclosures`):
  per source and per provider, in the client's own dialog. One check covers G6's own model calls, the MCP and CLI door,
  the cognitive bridge and the self-improvement loop's sessions. A disclosure record says what was sent.
- **The self-improvement loop over MCP** (`g6_improve_*`): the person agrees in the client's dialog to each start,
  enrolment, resume and demotion. The stop needs no dialog.
- **Allowances** (`g6_allowances`), **behaviour questions** (`g6_confirm_behaviour`), **missions and review**
  (`g6_mission_*`, `g6_premortem`, `g6_review_until_clean`), **the Context Engine** (`g6_knowledge_*`, 11 tools),
  **the workflow record** (off unless `G6_WORKFLOW_RECORD=on`) and **the cognitive bridge**, as in the earlier
  preparation note.
- **Tests cannot start a real host.** The suite points Claude Code and Codex at a program that does not exist.

### Migration (`claude/wire-clarity`)

Hosts matching `coding_agent_gate.verify_answer.verdict == "pass"` must handle `report_consistent` for consistent
caller assertions. `pass` now requires every test item to be observed through a host-bound G6 receipt. Read the
additive `evidence_status` per item and overall, and the MCP `decision` separately from the unchanged `ok` field.

## Known limits

[`v0.3.0-known-limits.md`](v0.3.0-known-limits.md) lists 171 reproduced findings, in 36 changes, that ship as known
limits: the 141 of the earlier preparation and 30 from the review loops of 2026-11-16 to 11-21, each of these with its
branch and the reviewer's test. Each one
fails in the safe direction (G6 refuses, withholds or reports less), needs code already running in G6's own process,
is a narrow platform edge ending in an error, is a narrowed race, or needs a certificate-bound file. The same page
lists the parts that are not measured and the MCP tools that always refuse on a fresh installation.

Also known, beyond the ledger:

- **Tools that refuse on a fresh installation.** Over MCP, `g6_simulate` always refuses
  (`G6_E_SELF_MODEL_INPUTS`): the server supplies no trusted measured snapshot. `g6_research_start` refuses while
  research authority is off, which is the default, and the server configures no research runner. `g6_distill_start`
  refuses failures recorded over MCP (`G6_E_SYNTH_TRAINING_ONLY`), because it needs independent training failures and
  `g6_failure_record` records self-observed ones; it also needs the person's allowance to run code.
- **Distillation's consent declarations wait for issuance.** The twelve distillation tools are not yet declared in
  `core/consent_declarations.py`, a certificate-bound file; they join it at the issuance window.
- **Model proposals stay lexical by default.** `rerank="auto"` and `propose="auto"` do not call the model until a
  certificate-bound consent fix lets G6 ask the consent check without acting. The model path needs `rerank="model"`
  or `propose=true`.
- **The override kernel's reach is narrowed.** Cloud endpoints and the Anthropic SDK are refused for overrides until
  a transport with one total deadline exists.
- **The default model covers model calls without tools only.** The MCP client's name is self-declared, and the
  same-provider rule assumes the processes belong to the same user. Installation alone does not establish a working
  sign-in.
- **Route suggestions without a model.** After the `using-g6` split, 10 reviewer tasks no longer get the route the
  pre-split corpus gave them from lexical ranking alone. The remedy is the model rerank, to be measured in dogfooding.
- **The command line gained three commands on the distillation line** (`g6 library`, `g6 research`, `g6 self-model`)
  while the CLI is frozen. TODO (lead): keep with a ruling, or remove.
- **Isolation on Windows.** The AppContainer boundary needs an access grant to read the interpreter, the environment
  and the source tree. Linux CI runs the bubblewrap tests; the AppContainer tests skip there by design.
- The items listed in the earlier preparation note still stand: confirmed behaviour checks ending
  `insufficient_evidence` or `not_run` on the Windows test machine, agent runtimes looking up their program before the
  consent check, the state-path race between two processes on Windows, and the issuance-window items.

## Not yet measured

These parts ship switched on, or built and wired, and have not had their measurement run. A passing test establishes
only the behaviour it covers. None of them is claimed to improve outcomes, and no copy may claim a distillation or
learning benefit.

- **The distillation study.** The three-arm study (static, reflection only, compiled) on weakened tests has not run.
  Its two pilots closed without evidence:
  - M1 stopped under its stop rule: 13 real bug fixes from 6 repositories gave 3 labels in 1 repository, below the
    3 repositories the rule needs (`validation/distill/pilot/M1_REPORT.md` on `claude/pilot-funnel`).
  - M1b closed at acquisition: none of its 9 acquisition bugs passed the fixed-suite stage, so no label was read
    (`validation/distill/pilot/m1b/M1B_RESULT.md` on `claude/m1b-roles`).
  - So there is no measured unseen-failure detection, transfer, reuse or net gain from distillation.
- **The learning loop** and `g6_select`'s ranking with recorded history.
- **The moment-of-need trials (F0).** The before and after arms on Claude Code and Codex have not run; only pilots ran.
- **Routing.** The held-out routing sets (48 utterances, and 12 for the vendored superpowers skills) are frozen but
  not scored on the release candidate.
- **The model by default** and the model proposals: route accuracy with and without the model.
- **The repair block's resolution rate** in real sessions.
- **Carried from the earlier note:** the self-improvement loop (an unattended week; adoption of what it proposes),
  allowance pacing against real provider windows, consent in a real client's dialog, the Context Engine's retrieval
  quality, the workflow record's suggestions, and behaviour questions with real people.
