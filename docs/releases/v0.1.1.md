# v0.1.1 preparation — not published

The existing public v0.1.0 tag and release remain immutable. Do not delete, recreate or move them.
Do not recommend v0.1.0 for independently enforced verification or cross-platform isolation guarantees.
This notice is in the repository; no public GitHub release description has been edited by this work.

Changes prepared for v0.1.1:

- Trust-door enforcement, scoped verification receipts, child environment/descriptor restrictions,
  Linux bubblewrap support and explicit refusal when isolation is unavailable.
- Strict composition with explicit mappings, semantic evidence declarations and scoped assurance reports.
- Data-only application construction, hypothesis-bearing code proposals, asynchronous evaluation/run jobs,
  digest-bound client consent and rollback, and terminal consent fallback.
- A Python patch-review reference that runs tests and reports unresolved scope rather than authorizing merges.
- Client registration using the installed interpreter and skills for Claude Code and Codex.

Release gates remain independent:

| Gate | Required evidence |
|---|---|
| Software | Split regression suites, built-wheel install smoke, supported dependency versions |
| Isolation | Actual Windows and Linux adversarial probes; skips do not count as passes |
| Client consent | Real supported Claude Code and Codex behavior, including decline and missing elicitation |
| Usability | Fresh-user install/discover/invoke/compose/read journey without manual debugging |
| Utility | Correctness, false assurances, failure recovery, cost and time against a stated baseline |
| Broader usability | Later ten-journey trial: 8/10 usable, zero unexplained errors; exploration is not successful tuning |
| Artifacts | Docs and bundles match the tested commit; stale certificates regenerated through their normal checks |

Known limits: code activation needs an independently configured safety evaluator; generic code correctness is not
proved; same-user local settings are not authenticated authorization; real-client usability and application utility
must not be inferred from unit tests. Python support remains 3.12–3.13. No paid V8 run or public release is implied.

The five certificates have now been renewed against the final 0.1.1 bytes after independent delta review
and 150 passing checks. All retain qualified-draft status and their existing scope limits. The independent
source findings retain their original attribution; the new reader reviewed implementation changes and the
version change, not the original source clauses again. See RELEASE_TRIALS.md for release evidence.

Release automation now checks that a version tag exactly matches a stable source version, refuses to replace
an existing GitHub release, and prepares a draft rather than publishing automatically. A failed partial draft
requires explicit owner reconciliation before retrying; the workflow does not delete or overwrite it.
