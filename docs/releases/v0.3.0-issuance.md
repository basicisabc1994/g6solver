# v0.3.0 certificate issuance window: frozen scope

This is the one certificate issuance window before 0.3.0. It is cut from `main` at 10c7457 (PR #9 merged). Nothing here
is tagged, released or published; merging, tagging and publishing stay the owner's steps.

Every one of the five vetted certificates (`adapt_physical_ai`, `duty_of_care`, `adapt_automl`, `adapt_bayesian`,
`adapt_sklearn`) binds `g6/__init__.py` and the core files below, so any change in this window means all five are
issued again through their normal checks.

## The order

1. Freeze this scope (this file).
2. The certificate-bound fixes, test first, each finding's reviewer test passing and the repository's own tests for the
   touched files passing.
3. Adversarial checks of the fixes on the integrated candidate.
4. An independent review of the window's whole change.
5. All five certificates issued again from the candidate's exact source, through their normal prechecks.
6. Artifact checks: certificates, catalogue and failure map match the candidate commit.
7. A pull request into `main`; the owner merges.

A certificate-bound change after step 5 means the certificates are evaluated again.

## Out of scope

- Anything not certificate-bound: it goes through ordinary branches into `main`.
- New features. A finding found here that needs more than a narrow fix is recorded and stays a known limit or is
  excluded, by the 11-09 release ruling.

## Evidence

Each finding's reviewer test was run on `main` (10c7457) before any change, each file alone, with the grants a
pre-consent test needs. The results, and the same tests on the candidate, go in the pull request.
