G6 engineers its own gains.

AI is usually judged by public benchmarks, and a high score there often fails to carry over to real work. So G6 never takes a score on trust: every change it makes is tested on tasks held out from it.

Every study here asks one question: when G6 engineers the harness around a model for a task, how much better does the same model do? It counts every study run, the earliest included, and says which part of G6 did the work. Together they are a worked example, built to show what the system can do; on your own work, results will vary with the task and the data you have. How to read them

Where one instruction fixes the main failure, self-tuning finds it, and its gate confirms the gain quickly: on GSM8K, asking for the working step by step, with the answer on its own last line, was enough. Where the gain comes from structure, examples of sixty similar labels or a loop that runs the code against tests, it is spread across more tasks, and the gate needs more evidence: self-tuning did propose labelled examples for MASSIVE and test-and-repair for MBPP, but with 70 held-out tasks its gate could not yet confirm them. G6's prebuilt components are those layers ready-made. Switched on together, they beat self-tuning task by task on {% for name, wins, losses in facts.components_vs_tuning %}{{ name }} ({{ wins }} gained, {{ losses }} lost){% if not forloop.last %} and {% endif %}{% endfor %}.

This supports the Swiss cheese design G6 is built on: each prebuilt component is a layer against one kind of failure, several are needed where one alone is not enough, and the structure of the task decides which layers matter. It is why G6 offers both modes, and why it tests both on your own examples.

Development round {{ both.round }} measured the two modes together, and they did not stack: self-tuning that started from every prebuilt component had {% if both.approved_from_components %}{{ both.approved_from_components }} change{{ both.approved_from_components|pluralize }} approved{% else %}no change approved on any of its {{ both.datasets }} task sets{% endif %}, and on {{ both.worst.dataset }} every component on did worse than the model alone ({{ both.worst.components }} against {{ both.worst.alone }} of {{ both.worst.n }}; {{ both.worst.lost }} tasks lost, {{ both.worst.gained }} gained). There a check asks every answer a second time with its own fixed question, so no instruction upstream could change the final label: one layer can mask another. The modes are alternatives, chosen per task on held-out evidence, not layers to switch on all at once.

How to read these results

A worked example: these studies show the power of G6's self-engineering on public tasks. They are not a forecast for yours.

What they are Claude Code working with G6 on one 8-billion-parameter local model ({{ facts.model }}) and public task sets. Every score is on fresh tasks that no tuning step saw, against the same model alone. One adaptation study was registered before it ran; the development rounds were not, and the method was improved between them. Each task set's winning option is picked after the fact from the options measured.
What they show
  • Where a model fails in a systematic way, G6 can engineer a large gain in minutes, on the same model: {{ facts.largest.0 }} went from {{ facts.largest.1 }} to {{ facts.largest.2 }} of {{ facts.per_dataset }} in the registered study.
  • The gate decides on evidence, whoever proposes a change: random changes put through it were approved when they won on held-out tasks and refused when they did not. G6's own reflective tuning found more than random search overall ({{ facts.total.D }} against {{ facts.total.F }} of {{ facts.n }} tasks in the registered study), but not on every task set.
  • The winning approach follows the task's structure: one instruction where a single change fixes the main failure, prebuilt components where the gain needs layers such as labelled examples or test-and-repair. The registered study supports G6's Swiss cheese design of prebuilt failure layers.
  • The two modes are alternatives, not a stack: in development round {{ both.round }}, self-tuning that started from every prebuilt component had no change approved, and on {{ both.worst.dataset }} every component on did worse than the model alone. Which mode wins depends on the task.
  • A small model can be bootstrapped through its harness: larger models engineer it, and the small model runs inside it alone, with no weights changed.
What they do not show How G6 does with other models, on your tasks, or with independent coding agents, or that a harness tuned for one task set helps another. Nor do they show that a harness adds knowledge a model lacks: much of each gain is the model doing what it can already do, once it is asked the right way. With 100 tasks per set, a difference of a few tasks can be chance; the large gains are not. The earlier benchmark studies were audited, not run again.
Why results vary G6 can only engineer what your checks and examples can measure: it needs about 30 or more held-out examples with known answers before it will approve a change. Gains are largest where errors are systematic and a harness change addresses them, and smallest where the model is already near its ceiling or lacks the knowledge a task needs.
Status The experiments are complete: the programme closed with development round 3, and the numbers here are final.

How every component meets the four hard problems of self-improvement

ProblemWhat every component does about it
Turning weak or partial evidence into reliable learning signalsEvery failure it catches is written to the run ledger as a labelled incident with its evidence and its failure mode: the input the meta-harness and the theory loop learn from.
Evaluators the adapting system cannot influenceIts checks are its own code, pinned by digest, or an outside tool (tests, a prover, a renderer), never written or tuned by the model being checked.
Transfer of learned safeguards to unseen task familiesA safeguard is bound to a failure mode, not to a task, so it applies wherever that mode can occur; its catch rate is measured on task families it was not built on.
Enough held-out examples to tell a real improvement from noiseIts catch rate and false-alarm rate are judged by G6's sequential test, which says how many more cases it needs instead of guessing.

The papers are design rationale: their proofs are not machine-checked, and none is cited as evidence.
