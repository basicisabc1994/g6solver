Get started

G6 works with the AI you already run, so there is nothing to replace. Add it, and your agent can check its own work, gate its actions and engineer itself to your task.

For a coding agent, start here: before your agent says a Python change is done, it asks G6 to review the patch, shows you G6's report, and fixes what G6 reproduces. Merging stays your decision.

Early alpha. Individual capabilities have been tested; general application-level improvements have not yet been established.

Three ways to use G6, all on your own computer: from your agent, in your code, or as an app.

From your agent

Your agent calls G6's tools through its MCP server.

  1. Install

    G6 installs from a copy of its code; it is not on PyPI.

    git clone https://github.com/basicisabc1994/g6solver && cd g6solver pip install ".[all]"
    {% comment %}CORE_SANDBOX-01 (owner ruling, 2026-10-27: refused without a boundary unless the person allows it once): g6.core.confine's UNCONFINED_WARNING, word for word, as the README, g6 doctor and the sensitive-op help say it.{% endcomment %}

    Where no operating-system boundary can confine it (macOS, Linux without bubblewrap, and Windows before the one-time access grant), G6 refuses to run untrusted code for you (a patch, a generated script, a repository's tests) unless you allow it once with g6 setup. Code you allow then has your own rights: it can read your key file ~/.g6/.env and your other files, and its network guard works inside Python only. You are responsible for what you run. Patch review needs an operating-system boundary (Linux with bubblewrap, Windows after the one-time access grant): allowing unconfined runs does not make it run, and on macOS it refuses. g6 doctor says whether that code runs confined on your computer: on Linux, install the bubblewrap package for the boundary; on Windows, it prints the one-time commands that grant the access. Then run g6 setup once yourself, not your agent: where your computer has no boundary, it asks whether G6 may run such code without one.

  2. Connect Claude Code or Codex

    Run this yourself, in a terminal, with --client codex for Codex, or give --client twice for both:

    g6 setup --client claude --allow patch_review.review

    It registers this installation with the client, with this installation's Python, installs the using-g6 skill for it, and allows patch review, the one sensitive operation the first review needs. Restart the client afterwards. Setup's last lines show the first review call.

    If the client already has an entry called g6, setup leaves it as it is and stops. See it with claude mcp get g6 (or codex mcp get g6). To replace it, remove it with claude mcp remove --scope user g6 (or codex mcp remove g6), then run g6 setup again.

  3. The first review

    In a Python repository, ask your agent for a change, then ask it to review the change with G6 before it says the task is done. The skill tells it how:

    1. It turns the task into numbered requirements, each with the pytest tests that check it where such a test exists.
    2. It calls g6_review_patch with the repository's folder, the task and the requirements, and polls metaharness_job until the review ends.
    3. It shows you the reply's readable report (assessment.report) as it is: what G6 reproduced first, then what is not established, then what you decide.
    4. When G6 reproduces a defect, it fixes it and reviews again, with each earlier reproduction added as a stated check, so you can see the fix pass the original counterexample. It stops after three rounds, when a round changes nothing, or when the report says only you can decide.

    G6 runs the tests with the repository's own .venv or venv; without one, with the Python running G6, which then needs pytest and the project's dependencies. For Poetry, conda or another environment, see G6_REPO_PYTHON in the workflow guide in the repository, docs/AI_FOR_AI_WORKFLOW.md.

    The outcome is one of: test integrity compromised, defect detected, insufficient evidence, or supported within scope. Supported within scope means every stated requirement passed its stated checks; it is not proof that the patch does everything the task needs. Merging stays your decision.

  5. Teach your agent to use G6

    The using-g6 skill tells your agent which G6 step to take at each point of its work; g6 setup installs it for Claude Code and Codex. To install it yourself, run this in your project to copy it into .claude/skills, where Claude Code finds it; add --user to have it in every project. For another agent, copy that folder to wherever it reads skills.

    g6 skills install

    For a coding agent, add the superpowers skills for the whole software lifecycle, which G6 ships with credit to their author (unless you already use the superpowers plugin):

    g6 skills install --with-superpowers

    g6 skills list shows every skill, including each component's own.

  6. Check it works

    Ask your agent which G6 tools it can see. It should list g6_review_patch, g6_find, g6_describe and g6_invoke, and the meta-harness tools.

In your code

Import one component into your own app, or tune a whole task with the meta-harness.

pip install . python -c "from g6.metaharness import adapt"

Where G6 itself calls a model, it uses the one you choose. Put these lines in your key file, .env in G6's folder (~/.g6/.env, or %USERPROFILE%\.g6\.env on Windows): a plain text file you create and only you edit. G6 reads keys only from that file, never from your shell or your agent's settings, so a key there is your go-ahead for G6 to use it. A paid provider uses your own account; G6 never picks one for you.
