G6 runs the tests the change touches, confined where your computer allows, looks for weakened tests, and shows each defect it reproduces with a command to check it yourself. A harness is everything around a model: what it sees, how its answers are checked, what it may do. Agents can propose application redesigns through four steps of controlled experimentation; improvement is not guaranteed.

  1. 1

    Propose

    G6 finds where your task goes wrong and drafts fixes: a sharper prompt, an extra check, a repair step.

  2. 2

    Test

    Each fix is compared with the baseline on registered held-out tasks. Independence depends on keeping those tasks from the proposer. When one loses, G6 says why.

  3. 3

    Gate

    A statistical gate keeps a fix only when it clearly beats what runs now.

  4. 4

    Approve

    Nothing changes until you say yes. Every change is recorded, and can be rolled back.

What happened when we tried it

We gave Claude Code with Claude Sonnet 5.5 ten recent, real bugs in black, pydantic, starlette, click, attrs and fastapi, with G6 over MCP. G6 reproduced no defect. Six of the ten patches failed the maintainers' tests: G6 asked for more evidence, accepted the patch within the checks the agent stated, or raised an alarm that turned out to be false. We fixed what it taught us.

That is G6 today: a careful, isolated check of what your agent states, not yet a defect finder. A second round turned on G6's own model, also Claude Sonnet 5.5, in every review of the same ten bugs: it proposed 51 checks, and none found a defect. Five of the ten new patches failed the maintainers' tests. Making G6 a defect finder is the self-improvement loop's first job. All ten runs

G6 maintaining G6, in public

We're building a loop in which G6 maintains its own GitHub repository. It finds where G6 falls short, has Claude Code and Codex work on the biggest gap in isolated containers, checks every change with G6's own review, and opens a pull request. A maintainer reviews and merges every change.

Everything is public: the code, the decisions, the evidence and the agents' transcripts. It's an open experiment in self-improvement infrastructure for AI agents, and we'll report what it shows, including if it doesn't help. Read the design

Start in two commands

No account and no hosted service: G6 runs on your computer.

First make G6's own environment with python -m venv --copies .venv and activate it. Get started shows the commands for each system.

git clone https://github.com/basicisabc1994/g6solver && cd g6solver pip install ".[all]" && g6 setup --client claude --allow patch_review.review

For Codex, use --client codex. The Get started page shows the first review.

  • In your code as a Python library
